## 首轮自动验收

必须实际运行：

```powershell
python -m unittest discover -s tests -v
python ../.system/skill-creator/scripts/quick_validate.py .
```

- 审计脚本测试全部通过，退出码为 0。

- `SKILL.md` frontmatter 只有 `name` 和 `description`，总行数不超过 240。
- 主文件链接四个 references，并说明读取条件。
- 运行时文本不含会凭空增加功能或用户反馈的旧示例。
- `README.md`、`LICENSE` 和 `.gitignore` 哈希不变。

自动脚本只覆盖词法差异。语义保真必须继续跑安全金标。

## 后续内容评估

后续建立 60 条语料：`public-account`、`xiaohongshu`、`spoken-script`、课程文案、`technical`、`academic` 各 8 条，再加 12 条本来就自然的负例。每类含明显模板、轻微问题和不应修改的正常用法。

### 指标定义

- 受保护信息保留率 = 正确保留的金标受保护项 / 金标受保护项总数。没有受保护项的样本不进入分母。
- 高置信信号减少率 = `(改写前命中数 - 改写后命中数) / 改写前命中数`。改写前为 0 的样本不进入分母；先按样本计算，再取宏平均。
- 实质改写率 = 至少一个事实词、谓词、限定或句序发生非格式变化的样本数 / 样本总数。只改空格、标点样式不算。
- 自然负例过度编辑率 = 被评审判为“没有必要且改变声音”的负例数 / 12。

### 目标

- 可自动核对的受保护信息保留率 100%。
- 新增事实、来源、反馈、经历和立场为 0。
- 高置信信号宏平均减少至少 60%。
- 自然负例过度编辑率低于 10%。
- 盲评中，增强版至少 70% 的有效样本在自然度和文体适配上优于旧版。

### 盲评规则

- 随机交换旧版与新版的 A/B 顺序，并隐藏版本信息。
- 每个样本由 3 名评审分别判断自然度、文体适配和保真。
- 两项都更好且保真不下降才记为胜；平局单独记录，不计入胜率分子。
- 缺失评分的样本不进入胜率分母，并报告缺失数。
- 任一评审发现事实或人格硬门槛失败，该样本直接判失败。

这些目标是后续非阻塞基线，不是行业标准。完成基线后再根据误判和评审一致性校准。
