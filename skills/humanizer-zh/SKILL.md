# Humanizer-zh

把中文文本改得更自然，但不替作者发明事实、经历或立场。

## 边界

本 skill 处理可观察的文本问题：模板化开场、聊天助手残留、空泛总结、机械结构、不合文体的表达，以及与样文不一致的形式特征。

不要：

- 判断文本由谁创作，或输出任何作者身份概率。
- 以规避第三方检测器为目标。
- 没有来源时补充案例、数据、引文、反馈、经历或观点。
- 为了“更有人味”强行加入第一人称、情绪、幽默或口语。
- 把所有文体改成同一种社交媒体口吻。

## 选择基础模式

三个基础模式互斥：

| 模式 | 何时使用 | 输出 |
|---|---|---|
| `diagnose` | 用户只要求审阅、检查、找问题或标出模板痕迹 | 只给诊断，不附改写稿 |
| `conservative` | 用户要求少改，或文本属于技术、学术、合同、政策等高保真场景 | 只修高置信问题，尽量保持结构和长度 |
| `natural` | 一般说明文、公众号、课程文案和常规润色 | 处理局部表达及篇章节奏；默认模式 |

选择优先级：用户明确指定的幅度 > 高保真文体约束 > 默认 `natural`。

`voice-match` 是叠加在 `conservative` 或 `natural` 上的修饰器，不是第四种基础模式。只有用户提供了足够样文或明确文风规则时才启用。两者都没有或不可用时，只移除该修饰器，基础模式不变。

## 判断渠道

渠道是附加参数，不是基础模式。可选值：`general`、`public-account`、`xiaohongshu`、`spoken-script`、`technical`、`academic`。

- 能从请求或文本可靠推断时直接选择。
- 渠道不影响高置信修改时继续处理，不追问。
- 不同渠道会显著改变结果时，只问一个问题。

## 硬门槛

### 事实保真

改写前锁定：

- 数字、日期、时间、金额、百分比。
- URL、邮箱、文件路径、代码标识符。
- 引文、姓名、机构、产品名、用户指定术语。
- 否定、概率、范围、条件、因果、归属和关键结论。
- 时间方向和状态变化，例如提前、推迟、取消、恢复、增加和减少。

不得把“可能”改成“必然”，把局部结论扩大到整体，或把他人观点改成作者断言。

复核失败时：

1. 回退或重写相关句。
2. 仍无法确认时保留原句，并强制说明未解决项。
3. 风险影响全文或无法定位时停止改写，降级为 `diagnose`。

### 人格保真

第一人称经历、身份关系、情绪、评价、立场和记忆是语义内容，不是文风。原文没有时，不得从样文迁移或自行添加。

## 处理流程

1. **确定编辑契约**：识别用途、读者、语气、基础模式、渠道、改写幅度和必须保留的信息。
2. **锁定事实**：记录可自动提取的项目和语义限定。
3. **篇章诊断**：检查宏大开场、段落功能雷同、重复总结、强行升华、过度对称和信息密度失衡。
4. **局部诊断**：检查聊天残留、讨好话术、空泛归因、抽象名词、连接词、句式、标点和格式。
5. **分级改写**：先处理高置信问题，再处理与当前文体冲突的中置信信号；自然句不动。
6. **可选文风适配**：只匹配样文中可观察的形式信号，不迁移语义内容。
7. **保真复核**：逐项核对受保护信息、限定、立场和人格。
8. **执行阻断与降级**：回退不安全改写；无法消除风险时保留原句或只输出诊断。

## 诊断与改写规则

高置信且通常可直接处理：正文中的聊天助手残留、训练截止免责声明、明显讨好话术、同段重复改述、无信息量的万能结尾。

中置信信号必须结合文体、密度和重复程度判断：emoji、三段式、粗体、“此外”“先说结论”、第一人称、短句和网络表达。它们不是硬禁词。

无来源的权威归因属于“高置信可诊断、非默认可删除”：

- 不补造来源。
- 不把“研究表明 X”改成作者断言“X”。
- 无法保持真值条件和归属时，保留原句并标注。

引文、代码、转录内容和用户要求保留的原话不自动修改，即使命中高置信短语。引文的分隔符和样式也原样保留，不把中文双引号换成单引号或其他形式。

改写遵循最小必要原则：删空话，保信息；优先简单动词和具体名词；改变节奏但不为变化而变化；不机械地把三项改成两项或四项。

## 输出

### `diagnose`

用紧凑表格或列表给出：原句、信号、置信度、理由、建议。不要附改写稿，不输出身份判断或概率。

### `conservative` / `natural`

默认只输出：

1. 改写后的完整文本。
2. 有帮助时补充 3-5 条普通改动说明。

任何保真失败、回退、原句保留或全文降级都必须说明，不受条数限制。

只有用户明确要求时才给逐句 diff 或评分。评分采用硬门槛加软指标；任何事实、限定或人格硬门槛失败都不得判为合格。

## 审计脚本

需要可重复的词法统计或原文/改写稿对比时运行：

```powershell
python scripts/audit_text.py --source original.txt --candidate revised.txt --json
```

只审计单篇文本：

```powershell
python scripts/audit_text.py --candidate revised.txt
```

脚本只统计模板信号并比较可确定提取的受保护信息。它会漏掉语义变化，warning 也不是自动裁决；必须继续人工复核姓名、结论、限定和立场。

## 交付前检查

- 是否新增了原文没有的事实、来源、经历、情绪或观点？
- 数字、日期、名称、术语、引文、代码和路径是否保留？
- 否定、概率、范围、条件、归属、时间方向和状态变化是否改变？
- 中置信信号是否按渠道判断，而不是机械删除？
- 已经自然的句子是否被无谓重写？
- 保真失败是否已回退并强制报告？
