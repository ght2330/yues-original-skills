# 状态语义问题分类

状态语义问题指：界面发出的状态信号和用户对当前任务、当前对象、操作归属的理解不一致。

审查时不要先问“代码怎么写”，先问“用户以为自己在操作什么”。

## A. 状态信号矛盾

定义：多个元素同时发出同一种高优先级状态信号，让用户分不清谁是当前对象。

常见表现：

- 多个同级列表项同时有 current/selected 背景。
- 当前项、hover 项、focus 项使用完全相同样式。
- 多个按钮同时像主按钮。
- tab、sidebar、breadcrumb 同时指向不同当前位置。
- loading 状态出现在多个对象上，但实际只有一个任务在运行。

判断问题：

- 用户是否会问“我现在到底在哪个对象里”？
- 下一步点击会影响哪个对象是否清楚？
- 当前态、选中态、悬停态是否能被区分？

修复方向：

- current、selected、hover、focus 使用不同 token。
- 同级对象同时只能有一个 current。
- 多选场景必须明确显示 selection count 或批量操作栏。
- loading 状态要贴近触发它的对象或任务。

## B. 操作入口噪音

定义：太多操作入口同时可见或高亮，导致用户无法判断操作范围和优先级。

常见表现：

- 每行都显示更多菜单、删除、编辑等按钮，列表显得所有项都在等待操作。
- 当前对象旁和非当前对象旁的菜单按钮同样突出。
- 多个层级同时出现主操作按钮。
- 危险操作和普通操作视觉权重接近。
- toolbar、row action、floating action 同时作用范围不清。

判断问题：

- 用户是否能在 1 秒内判断主操作是什么？
- 每个操作的作用对象是否明确？
- 非当前对象的操作是否抢了当前对象的注意力？

修复方向：

- 行操作默认隐藏，只在 hover/focus/selected 时显示。
- 批量操作只在选择后出现。
- 主操作每个区域只保留一个。
- 危险操作降低默认可见性，并在确认中说明影响对象。

## C. 对象身份混淆

定义：多个对象因为名称、图标、状态或布局过于相似，导致用户无法区分。

常见表现：

- 多个条目同名，没有时间、来源、路径、状态等次级信息。
- 不同对象使用相同图标和相同状态徽标。
- 搜索结果、聊天、文件、任务列表中重复项无法分辨。
- 当前对象标题和列表项标题不一致或无法对应。

判断问题：

- 用户能否把主内容区和列表中的对象一一对应？
- 重复名称是否有足够的辅助信息？
- 图标和徽标是否真的帮助区分，而不是增加噪音？

修复方向：

- 增加次级身份信息：时间、来源、路径、所有者、状态、版本。
- 当前对象标题和列表项保持可对应。
- 重复对象需要稳定排序和可识别差异。
- 不要只靠颜色区分身份。

## D. 瞬态状态泄漏

定义：临时交互状态在交互结束后没有清理，残留在界面上。

常见表现：

- 鼠标离开后 hover 背景仍保留。
- 菜单关闭后触发按钮仍像打开状态。
- 点击后 pressed 状态卡住。
- focus 留在不可见或已关闭元素上。
- loading 完成后 spinner、disabled、progress 仍残留。
- 路由切换后旧页面的选中态仍显示。

判断问题：

- 用户的注意力已经移动，界面是否还在强调旧对象？
- 打开/关闭、开始/结束、进入/离开是否有状态闭环？
- hover、focus、selected、current 是否被混用？

修复方向：

- 交互结束后清理临时状态。
- menu-open 和 hover 分离。
- focus 关闭后回到合理触发点。
- loading 成功或失败后恢复可操作状态，并显示结果。
- 路由和对象切换时重算 current/selected。
