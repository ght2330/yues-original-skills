# 示例

## 示例 1：多个同名列表项同时像当前对象

来源：用户提供的界面截图（示例文件不随仓库发布）

观察：

- 当前界面只有一个正在显示的对话。
- 左侧助手列表里有三个重复的“货币资金智能体”条目。
- 三个条目都显示了高强调背景。
- 多个条目也暴露了菜单按钮。

结论：

```text
[HIGH] 多个同名列表项同时发出当前/可操作信号
证据：当前只有一个对话打开，但左侧三个同名条目都有高亮背景和菜单按钮。
影响：用户无法判断哪个条目是当前对象，也无法确信菜单操作会作用于谁。
修复：只给当前会话保留 selected 背景；hover 菜单按钮仅在鼠标所在行或键盘焦点行显示；重复同名对象增加次级时间、来源或状态标识。
```

问题类型：

- 状态信号矛盾
- 操作入口噪音
- 对象身份混淆
- 可能存在瞬态状态泄漏

## 示例 2：按钮文字超出边界

观察：

- 按钮宽度固定。
- 文本换成较长中文或英文后越过按钮右侧。
- 图标和文字挤在一起，点击目标仍可用，但视觉上破裂。

结论：

```text
[MEDIUM] 按钮文本超出容器
证据：按钮宽度不足以容纳当前文案，文字越过右边界并接近旁边图标。
影响：用户会觉得按钮状态异常，也可能误读按钮文案。
修复：为按钮设置 max-width 与 text-overflow；如果文案是关键动作，允许按钮自适应宽度；如果空间固定，改成图标按钮并提供 tooltip。
```

## 示例 3：菜单关闭后触发按钮仍保持打开态

观察：

- 用户打开某行更多菜单。
- 关闭菜单后，触发按钮仍然保持深色背景。
- 鼠标已经移动到别处。

结论：

```text
[HIGH] 菜单触发按钮残留 open 状态
证据：菜单已经关闭，但触发按钮仍保持打开态背景。
影响：用户会误以为菜单仍在打开，或当前行仍处于特殊状态。
修复：将 menu-open 状态和 hover 状态分离；菜单关闭时清理 open 状态；非 hover/focus 行隐藏菜单按钮。
```

## 示例 4：浮层遮住关键内容

观察：

- 用户点击字段旁的帮助图标。
- tooltip 出现在字段上方，但遮住了字段值或错误提示。
- 用户需要移开鼠标才能继续看内容。

结论：

```text
[MEDIUM] tooltip 遮挡关键字段内容
证据：tooltip 打开后覆盖了字段值和错误提示。
影响：用户无法同时理解帮助说明和当前字段状态。
修复：为 tooltip 增加碰撞检测，优先放在不会遮挡字段值的位置；必要时改用侧边帮助面板。
```
