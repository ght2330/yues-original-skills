# 视觉几何与可读性检查

视觉几何问题指：界面元素的空间关系、尺寸、对齐、层级或文本适配出现破裂。它不一定是“审美不好”，而是用户能直接感受到“不稳”“挤”“歪”“挡住了”“字放不下”。

## 1. 位置与对齐

检查点：

- 元素是否在它所属容器内居中。
- 图标和文字是否在同一视觉中线或基线。
- 同组按钮、输入框、列表项、卡片是否对齐。
- 左右、上下留白是否明显不均。
- 标题、内容、操作区是否有清晰对齐线。

问题信号：

- 本应居中的图标偏上、偏下、偏左、偏右。
- 同一行里的文字和图标看起来不在一个水平线上。
- 按钮组中某个按钮高度或基线明显不一致。
- 列表项内容左右缩进忽大忽小。

修复方向：

- 用明确的 flex/grid 对齐规则。
- 为固定格式控件定义稳定高度、宽度、gap。
- 图标使用统一尺寸，并用容器对齐，不靠手调 margin。
- 文本和图标组合使用统一 line-height。

## 2. 尺寸比例

检查点：

- 按钮、图标、输入框、卡片、列表行高是否符合它们的信息层级。
- 同层级控件尺寸是否一致。
- 点击目标是否太小或太大。
- 侧栏、顶部栏、底部输入区是否挤压主内容。

问题信号：

- 图标比文字大太多，抢占注意力。
- 小按钮装了长文本，显得拥挤。
- 列表行过高导致信息密度异常低。
- 输入框或卡片在窄屏下占用过多空间。

修复方向：

- 为组件设定 size token：sm/md/lg。
- 同组控件统一高度、圆角、内边距、图标尺寸。
- 对固定工具按钮使用正方形尺寸。
- 对长文本按钮设置最小宽度、最大宽度和换行/截断策略。

## 3. 重叠、遮挡与层级

检查点：

- 文本、按钮、菜单、tooltip、popover、modal 是否互相遮挡。
- 浮层是否遮住触发对象或关键内容。
- 角标、状态徽标是否压住文字。
- fixed/sticky 元素是否挡住滚动内容。
- z-index 是否让下层元素覆盖上层浮层。

问题信号：

- 菜单打开后挡住用户下一步必须看的内容。
- tooltip 和按钮重叠，无法阅读。
- 输入框底部被固定栏遮住。
- 长标题和操作按钮撞在一起。

修复方向：

- 增加浮层碰撞检测或自动换边。
- 给滚动容器增加底部/顶部安全留白。
- 对标题和操作区使用 flex shrink/grow 约束。
- 明确 z-index 层级，不靠随机大数字。

## 4. 文本溢出与容器适配

检查点：

- 文字是否完整装进按钮、标签、卡片、列表项、输入框。
- 长词、长路径、长文件名、英文、中文、多语言是否都能处理。
- 省略号是否在合适的位置。
- 换行后高度是否稳定。

问题信号：

- 按钮文字超出边界。
- 标签文字盖住关闭按钮。
- 长文件名把右侧操作按钮挤出屏幕。
- 多语言文本导致卡片高度错乱。
- 省略号隐藏了关键信息，用户无法区分对象。

修复方向：

- 使用 `min-width: 0` 修复 flex 文本溢出。
- 使用 `overflow: hidden`、`text-overflow: ellipsis`、`white-space`、`line-clamp`。
- 对关键身份文本保留开头和结尾，例如路径、文件名、模型名。
- 为长文本提供 tooltip、展开或详情区域。
- 为按钮文本设置合理最大宽度，必要时换成图标+tooltip。

## 5. 视觉节奏

检查点：

- 同组元素的圆角、边框、阴影、间距是否一致。
- 同层级文本字号、字重、颜色是否稳定。
- hover/selected/focus/loading 是否会造成布局跳动。
- 动态内容出现后是否推挤周围元素。

问题信号：

- hover 后按钮变大，导致整行抖动。
- loading 文案替换后按钮宽度突变。
- 同一列表里有的行高 40，有的行高 52，但没有层级原因。
- 卡片之间间距不一致。

修复方向：

- 给动态元素预留稳定尺寸。
- loading 状态保持按钮宽度。
- 状态变化只改变颜色、描边、透明度，不随意改变布局尺寸。
- 同组元素统一 token。
